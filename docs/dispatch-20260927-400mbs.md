## Goal

**Make the open source DDR3 controller sustain >= 400 MB/s.** That is the
project requirement (see `README.md`).

## What is measured today

On hardware, Tang Primer 20K `GW2A-LV18PG256C8/I7`, device version C:

| direction | rate | bytes/command | pclk/command |
|---|---|---|---|
| write | 28.21 MB/s | 2 | 6.0 floor (85% of the 2 B/cmd ceiling) |
| read | 159.30 MB/s | 16 (`dout128`) | 10.0 |

Both are a command count times a bytes-per-command figure. **Write is the
binding direction** -- ~14x short, against ~2.5x on read.

## What is different about this repo (read this before planning)

This is a standalone project seeded from upstream `a6d866d`, plus ONE change we
already pushed: `src/ddr3_controller.v` now has an `accept` output, a one-cycle
pulse at the IDLE -> READ/WRITE transition, i.e. exactly one pulse per command
actually taken in. `wr`/`rd` are LEVEL signals held for the whole busy window
and over-count by ~3.35x. **Every rate divides by `accept`, never by
busy-cycles.**

There is deliberately NO legacy here: no old measurement harness, no vendor-core
adapter, no consumer RTL, no prior project's conventions. `tools/bench.sh`
(exclusive bench lock) and `tools/fpga-run.sh` (container wrapper) are the only
tooling that came across. Build the measurement path from the ground up.

Upstream ships an iverilog simulation (`simulation/`) -- use it.

2. **Make the on-chip command count readable.** Put the command counter on the

   denominator of every throughput number, and it currently carries an
   unexplained factor of 1.0132.
3. Implement, build, measure on the bench, commit evidence.

Candidate directions -- yours to accept, reject or replace, but the design note
must say why:

- more bytes per write command (the write payload is genuinely 1x16-bit word per
  command today because BC4 plus DM masks 3 of 4 beats),
- more than one command in flight (the controller is strictly one-in-flight:
  no queue, no pipelining, `busy` for the whole window),
- lower per-command cost (`busy` negates at 24 pclk for write per the RTL
  comment, ~8 for read; measured floors are 6.0 and 10.0),
- keeping the row open instead of auto-precharging every command.
